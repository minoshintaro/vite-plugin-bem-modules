# vite-plugin-bem-modules

[English](./README.md) | 日本語

ViteのCSS Modulesを使いながら、出力するクラス名を`c-card`、`c-card__title`、`c-card--compact`のようなBEM名に固定するプラグインです。

コンポーネントでは通常のCSS Modulesと同じように`styles.root`や`styles.title`で参照できます。隣接する型宣言も生成できるため、クラス名の補完と存在確認をTypeScriptへ組み込めます。

```css
/* @block c-card */

.root {}
.root--compact {}
.title {}
```

```ts
styles.root;        // "c-card"
styles.rootCompact; // "c-card--compact"
styles.title;       // "c-card__title"
```

`@block`コメントを書いた`.module.css`と`.module.scss`だけがBEM変換の対象です。コメントのないCSS Module、通常のCSS、依存パッケージ内のCSS ModuleはViteの標準処理へ委ねます。

## 対応環境

- Vite 8.x
- Node.js `^22.13.0`または`>=24.0.0`
- `.module.css`と`.module.scss`
- Viteの既定PostCSS transformer

SCSSを使う場合は、Viteが利用できるSass処理系も必要です。

```sh
pnpm add -D sass-embedded
# または
npm install -D sass-embedded
```

`css.transformer: "lightningcss"`には対応していません。

## インストール

```sh
pnpm add -D vite-plugin-bem-modules
# または
npm install -D vite-plugin-bem-modules
```

## クイックスタート

### 1. ViteプラグインとPostCSSプラグインを登録する

`vite.config.ts`または`vite.config.js`に、ViteプラグインとPostCSSプラグインの両方を登録します。

```ts
import { defineConfig } from "vite";
import bemModules, { createBemPostcssPlugin } from "vite-plugin-bem-modules";

export default defineConfig({
  plugins: [bemModules({ types: true })],
  css: {
    postcss: {
      plugins: [createBemPostcssPlugin()],
    },
  },
});
```

`createBemPostcssPlugin()`の明示登録は必須です。既存のPostCSSプラグインがある場合は、同じ`plugins`配列の実行したい位置へ追加してください。このプラグインは配列の順序を変更しません。

### 2. CSS ModuleにBlock名を書く

`Card.module.css`を作り、`@block`コメントで出力するBlock名を指定します。Block名をファイル名から推測することはありません。

```css
/* @block c-card */

.root {
  display: grid;
  gap: 12px;
  padding: 16px;
}

.root--compact {
  gap: 4px;
  padding: 8px;
}

.title {
  font-weight: 700;
}
```

クラスは次のように変換されます。

| CSS Moduleのクラス | 出力されるクラス | コンポーネントからの参照 |
| --- | --- | --- |
| `.root` | `c-card` | `styles.root` |
| `.root--compact` | `c-card--compact` | `styles.rootCompact` |
| `.title` | `c-card__title` | `styles.title` |

`root`はBlockそのものです。それ以外のBaseクラスはElementになり、Modifierには対応するBaseが必要です。たとえば`.title--large`を定義する場合は`.title`も定義します。

### 3. コンポーネントから参照する

既定の`modifierOutput: "only"`では、Modifierの値にBaseクラスを含めません。両方のスタイルを使うときはBaseとModifierを並べます。

```tsx
import styles from "./Card.module.css";

type CardProps = {
  compact?: boolean;
  title: string;
};

export function Card({ compact = false, title }: CardProps) {
  const className = compact
    ? `${styles.root} ${styles.rootCompact}`
    : styles.root;

  return (
    <article className={className}>
      <h2 className={styles.title}>{title}</h2>
    </article>
  );
}
```

## 型宣言を運用する

管理対象のCSS ModuleをViteが処理すると、元ファイルの隣に`Card.module.css.d.ts`のような型宣言を生成できます。

```ts
// Generated by vite-plugin-bem-modules. Do not edit.
export type Styles = {
  readonly "root": string;
  readonly "root--compact": string;
  readonly "rootCompact": string;
  readonly "title": string;
};

declare const styles: Styles;

export default styles;
```

型宣言に含まれる安定したAPIはクラスのキーだけです。ID、keyframes、`@value`、任意のICSS `:export`は含めません。

| 実行方法 | `types` | 動作 |
| --- | --- | --- |
| Vite dev server | 省略または`true` | Viteが処理した管理対象Moduleの型を生成・更新する |
| Vite build | `true` | buildで処理した管理対象Moduleの型を生成・更新する |
| Vite build | 省略 | 既存の型宣言を変更しない |
| Vite dev server / build | `false` | 処理したModuleの生成済み型を削除する。buildでは対象範囲も掃除する |
| `bem-modules sync` | ― | 対象範囲のCSS Moduleを全走査して型を同期する |

生成された`.d.ts`は手編集せず、リポジトリへコミットする運用を推奨します。clone直後でもエディタと`tsc`がクラスの型を読めるためです。手書きファイルやsymlinkが生成先にある場合は上書きせず、`BEM006`で停止します。

### 未importのCSS Moduleも同期する

Viteのdev serverとbuildは、実際に処理したModuleだけを生成対象にします。importされていない`.module.css`を含めて検査・同期する場合は、同梱CLIを使います。

```json
{
  "scripts": {
    "bem:check": "bem-modules check",
    "bem:sync": "bem-modules sync"
  }
}
```

```sh
pnpm bem:check
pnpm bem:sync
```

- `check`: 対象ファイルを検査する。型宣言は変更しない
- `sync`: 検査後に型宣言を生成・更新し、対象範囲内の孤立した生成物を削除する

型宣言は型検査の入力です。CSS Moduleやクラスキーに影響する設定を変えたときは、`bem-modules sync → tsc → vite build`の順に実行します。生成された宣言をコミットしておけば、変更のない通常のbuildで毎回`sync`する必要はありません。CIでは`sync`を実行し、生成物に差分がないか確認すると古い宣言を検出できます。`types: true`によるbuild中の生成は補助機能として使えますが、そのbuildより前の型検査には間に合いません。

CLIは、対象範囲のCSS / SCSS Moduleをvirtual entryからimportする一回のVite `write: false` buildとして動きます。Sassの展開、`additionalData`、alias、custom importer、PostCSSの順序、CSS Modules、worker lifecycleはViteへ委譲します。CIで`.module.scss`を含むscopeを検査する場合は、Viteが利用できるSass実装（`sass-embedded`など）を依存に含めてください。

このbuildはViteの`command: "build"`と既定の`mode: "production"`で設定を読み、Vite config内の他plugin hookも実行します。CLI用に副作用のないVite configを使うか、必要なら`--vite-config <path>`で専用configを指定してください。

`--config`は従来どおり`bem-modules.config.mjs` / `.js`を指定します。Vite configは`--root`からViteの標準探索で読み込み、明示指定が必要な場合だけ`--vite-config <path>`を使います。`bemModules(...)`、`createBemPostcssPlugin()`、CLIでは同じ設定objectを共有してください。CLIは標準Vite companionの`plugins`登録と、`css.postcss.plugins`への直接登録の一つを必要とし、既存の両方をcapture用に再利用します。Vite configがない場合、外部PostCSS設定だけの場合、companionがない場合、または別の間接登録の場合は`BEM010`で停止します。CLIはcompanionやPostCSS factoryを追加せず、外部PostCSS設定も探索・コピー・再構成・上書きしません。

### ViteとCLIで設定を共有する

CLIも使う場合は、設定を`bem-modules.config.mjs`へ置き、Viteから同じオブジェクトを読み込みます。

```js
// bem-modules.config.mjs
export default {
  types: true,
  naming: {
    wordCase: "kebab",
  },
  project: {
    include: ["src"],
    exclude: ["src/fixtures"],
  },
};
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import bemModules, {
  createBemPostcssPlugin,
  defineBemModulesConfig,
} from "vite-plugin-bem-modules";
import config from "./bem-modules.config.mjs";

const bemConfig = defineBemModulesConfig(config);

export default defineConfig({
  plugins: [bemModules(bemConfig)],
  css: {
    postcss: {
      plugins: [createBemPostcssPlugin(bemConfig)],
    },
  },
});
```

CLIでは`--root`、`--config`、繰り返し指定できる`--include`と`--exclude`も利用できます。

## 主な設定

設定は`bemModules(options)`へ渡します。Viteプラグインが同じ設定を、登録済みのBEM PostCSSプラグインへ適用します。

| 設定 | 既定値 | 用途 |
| --- | --- | --- |
| `modifierOutput` | `"only"` | ModifierのexportにBaseを含めるか選ぶ |
| `naming.wordCase` | `"camel"` | local classをcamelCaseまたはkebab-caseで記述する |
| `naming.elementSeparator` | `"__"` | 出力名のBlockとElementを区切る |
| `naming.modifierSeparator` | `"--"` | 入力名と出力名のModifierを区切る |
| `globalScope.exact` | `[]` | 完全一致したクラスをBEM変換から除外する |
| `globalScope.prefix` | `[]` | 指定した接頭辞のクラスをBEM変換から除外する |
| `types` | 実行方法による | 隣接型を生成、維持、削除する |
| `project.include` | `["."]` | CLI同期と範囲単位の掃除に含めるファイルやディレクトリを指定する |
| `project.exclude` | `[]` | 対象範囲からファイルやディレクトリを除外する |

`project.include`と`project.exclude`はglobではありません。Viteの`root`からの相対パス、または絶対パスでファイルやディレクトリを指定します。`include: []`は空の対象範囲です。

この対象範囲はCLI同期と生成型の掃除に使います。ViteがimportしたModuleをBEM変換するかどうかは制限しません。Viteの処理経路では、実体ファイルの`@block`コメントが所有の境界です。

### Modifierの値にBaseを含める

```ts
bemModules({
  modifierOutput: "withBase",
});
```

この設定では、`styles.rootCompact`が`"c-card c-card--compact"`になります。`styles.root`を追加するとBaseが重複するため、Modifierだけを指定します。

### kebab-caseでクラスを書く

```ts
bemModules({
  naming: {
    wordCase: "kebab",
  },
});
```

```css
/* @block c-card */

.root {}
.profile-image {}
.profile-image--rounded {}
```

JavaScript / TypeScriptではcamelCaseのキーも利用できます。

```ts
styles.profileImage;
styles.profileImageRounded;
```

separatorには`"-"`、`"--"`、`"_"`、`"__"`を指定できます。ElementとModifierに同じ値は使えません。`wordCase: "kebab"`では単一の`-`が単語区切りになるため、`modifierSeparator: "-"`は指定できません。

### BEM変換しないクラスを使う

CSS Modules標準の`:global(...)`を利用できます。

```css
/* @block c-card */

:global(.utility) .title {
  display: block;
}
```

既存の規約に合わせて設定で除外する場合は、`globalScope`を使います。

```ts
bemModules({
  globalScope: {
    exact: ["active"],
    prefix: ["is-", "has-"],
  },
});
```

`root`は常にBlockを表す予約語なので、`globalScope`に一致してもBEM変換されます。

`globalScope`に一致するclassは、名前をglobal化しながらも、互換APIとしてpluginのlocal class APIとclass-onlyの`.d.ts`へ元のkeyで残ります。これは、明示した`:global(...)`のclassがpluginのclass APIへ追加されない動作とは異なります。

## CSSとSCSSの扱い

### ViteのCSS処理経路をそのまま使う

SCSSのコンパイル、alias、`additionalData`、custom importer、PostCSS、CSS Modules、HMRはViteが処理します。このプラグインは別のSassコンパイラを起動せず、ViteがPostCSSへ渡した実際のASTを変換します。そのため、mixinが出力したクラスも実行時のCSSと型宣言へ同じ結果で反映されます。

### Sassでは完全なクラス名を書く

BEM対象のクラス名は静的に確定できる形で書いてください。

```scss
/* @block c-card */

.root {}
.root--compact {}
```

次の書き方には対応しません。

```scss
.root {
  &--compact {}
}
```

`&--modifier`、selector補間、`@at-root`、`@extend`は`BEM005`で拒否します。宣言を共有する場合は、selectorを継承しないmixinを利用できます。

### IDとkeyframesはグローバル名になる

BEM対象Module内のIDとkeyframesはCSS Modulesのlocal exportにせず、記述した名前をグローバルに維持します。`animation`と`animation-name`の参照も同じ名前へ変換します。

複数の処理済みBEM Moduleが同じkeyframes名を定義すると警告しますが、buildは停止しません。名前の衝突は通常のCSS cascadeとanimationの規則に従います。

### 生成クラスもグローバル名になる

生成するBEMクラスにはCSS Modulesのhashを付けません。異なるModuleから同じBlock名やクラス名を出力することも許容します。衝突した場合は、通常のCSSと同じcascadeの規則で結果が決まります。

### 通常のCSS Modulesと併用する

`@block`のない`.module.css`と`.module.scss`はBEM変換しません。Viteの通常のCSS Modulesとして、同じプロジェクト内で併用できます。

```css
/* Plain.module.css: @blockなし */
.root {
  color: rebeccapurple;
}
```

通常のCSS、`node_modules`内のCSS Module、実体ファイルを持たないvirtual CSS Moduleもこのプラグインの所有外です。

## v0.1からv0.2へ移行する

v0.2では、Sass、PostCSS、CSS Modules、HMRをViteへ委ねる構成へ変更しました。移行時は次の差分を確認してください。

1. `createBemPostcssPlugin()`を`css.postcss.plugins`へ明示登録する必要があります。
2. 生成型の安定したAPIはクラスのキーだけです。ID、keyframes、`@value`、任意のICSS `:export`を参照していた場合は、CSSまたは別の型定義へ移してください。
3. Module間で同じBlock名や生成BEMクラス名を使っても、Project全体の一意性エラーにはなりません。グローバル名の衝突はCSSの通常規則で解決されます。
4. CLIもViteの`write: false` programmatic buildを一度だけ実行し、virtual entryからscope内の全Moduleをimportします。SCSSの型生成にはViteが選んだSass実装が必要です。
5. 通常の更新とHMRはViteへ委譲します。プラグイン独自のCSS HMRランタイムやimporterの無効化処理はありません。

公開設定の`naming`、`globalScope`、`modifierOutput`、`types`、`project`は引き続き利用できます。`project.startup`も設定互換のため受け付けますが、v0.2のViteプラグインは起動時にProject全体のCSS / SCSSを別の処理経路で扱いません。未importのCSS ModuleはCLIで明示同期してください。

## 対応していない機能

- CSS Modulesの`composes`
- BEM対象Moduleへの`?raw`、`?inline`、`?url`
- Sassの`&--modifier`、selector補間、`@at-root`、`@extend`
- `css.transformer: "lightningcss"`
- Viteが利用できるSass実装を使わない単独CLIでのSCSS検査・型同期
- frameworkが生成する`<style module>`など、実体パスのないvirtual CSS Module

import中のCSS Module自体を削除すると、import解決が失敗します。隣接型と内部登録は掃除しますが、呼び出し側のimportを自動修正することはありません。

## 診断コード

エラーには`[vite-plugin-bem-modules:BEMxxx]`形式のコードが付きます。

| コード | 意味 |
| --- | --- |
| `BEM001` | `@block`の名前が空または不正 |
| `BEM002` | 1つのModuleに`@block`が複数ある |
| `BEM003` | クラス名、Modifier、Block名、生成名の規則違反または衝突 |
| `BEM004` | 設定値、実行方法、または対象機能が対応範囲外 |
| `BEM005` | 動的なSass selectorまたは`@extend`を検出した |
| `BEM006` | 隣接型がプラグイン所有の通常ファイルではない |
| `BEM007` | `composes`が使われている |
| `BEM008` | BEM対象Moduleに非対応クエリが付いている |
| `BEM010` | BEM PostCSSプラグインが明示登録されていない |
| `BEM011` | Lightning CSS transformerが指定されている |

## 公開API

| API | 用途 |
| --- | --- |
| default export `bemModules` | Viteプラグインを作る |
| `createBemPostcssPlugin` | BEM変換を行うPostCSSプラグインを作る |
| `defineBemModulesConfig` | ViteとCLIで共有する設定に型を付け、そのまま返す補助関数 |
| `isBemGlobalClassName` | `globalScope`とクラス名の一致を判定する |
| `BemModulesOptions`ほか公開型 | 設定をTypeScriptで記述する |

Compiler、Project、schema、keyframes台帳などの低レベル実装は公開APIではありません。
